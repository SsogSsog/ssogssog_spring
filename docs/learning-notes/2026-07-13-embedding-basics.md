## 1. 임베딩 (Embedding)

**텍스트를 그 의미를 담은 고차원 벡터(float 배열)로 바꾸는 것.** 의미가 비슷한 텍스트는 벡터 공간에서 가까이 위치한다.

- 단어 하나가 아니라 **문장·구(phrase) 전체의 의미**를 벡터 하나로 압축. (오늘 "삼성전자 실적"이라는 구 전체가 벡터 1개 = 3072개 숫자로 나옴)
- 3072개 숫자 각각은 사람이 해석할 수 없는 "의미 좌표". 중요한 건 개별 숫자가 아니라 **벡터끼리의 상대적 위치**.

**면접용 한 문장**: "텍스트를 의미를 담은 고차원 벡터로 바꾸는 것. 의미가 비슷한 텍스트는 벡터 공간에서 가까이 위치하게 됩니다."

---

## 2. 코사인 유사도 (Cosine Similarity)

**두 벡터가 이루는 각도(방향)만 측정.** 각도가 좁으면(같은 방향) 유사, 벌어지면 무관. 범위 -1 ~ 1 (1에 가까울수록 유사).

- 공식: `dot(a,b) / (‖a‖ · ‖b‖)`
  - `dot(a,b)` = Σ a[i]·b[i] (내적)
  - `‖a‖` = √(Σ a[i]²) (벡터 크기)
- **"거리(유클리드 거리)"와 헷갈리지 말 것.** 코사인은 거리를 일부러 무시하고 방향만 본다.

**왜 길이(크기)를 무시하나** (핵심 포인트):
텍스트가 길면 벡터 크기가 커지는 경향이 있는데, 그건 **의미가 아니라 텍스트 양** 때문. "삼성전자 실적"과 "삼성전자의 최근 분기 실적이 궁금합니다"는 길이는 다르지만 의미는 같음. **방향만 보면 길이 차이에 안 속고 의미만 비교**할 수 있어서 코사인을 씀.

**실무 주의**: 코사인 유사도는 직접 구현하지 않는다. pgvector가 `<=>` 연산자로, Spring AI가 내부적으로 제공. 오늘 손으로 짠 건 원리 이해용 1회성.

## 3. 왜 Vector DB인가 (vs MySQL LIKE)

`WHERE ... LIKE '%키워드%'`는 **글자(문자열) 매칭**이라, `"실적"`으로 검색하면 `"영업이익"`이 들어간 문서를 **놓친다** (글자가 안 겹치니까). 하지만 둘은 의미가 가깝다.

- **LIKE = 키워드(글자) 검색** → 정확히 같은 글자만 찾음
- **벡터 검색 = 의미(semantic) 검색** → 글자가 안 겹쳐도 의미가 가까우면 찾음

→ 공시 10만 건에서 "질문과 의미가 비슷한 문서"를 찾으려면 벡터 검색이 필요.

## 4. 임베딩 모델 교체 시 재적재 (운영 포인트)

**임베딩 모델을 바꾸면 저장해둔 벡터를 전부 다시 임베딩해서 재적재해야 한다.**

이유: 모델마다 벡터 공간이 완전히 다르다. 차원 수도 다를 수 있고(예: 3072 vs 768), 같은 텍스트라도 좌표가 전혀 다름. **A 모델로 저장한 문서를 B 모델로 만든 질문 벡터로 검색하면 유사도가 엉망**이 된다 (서로 다른 언어로 쓰인 지도를 겹쳐놓는 꼴).

→ "모델 교체 = 전체 재적재 비용"이 실무 의사결정 요소. 포폴 **"한계 인식"** 섹션 항목.

## 5. 직무 방어 프레이밍 (면접)

Q. "임베딩 유사도 직접 구현해보셨어요?"

> "코사인 유사도를 직접 구현해보면서 원리는 이해했지만(내적을 크기 곱으로 나눠 방향을 재는 것), 실무에선 pgvector가 인덱스까지 최적화해서 제공하기 때문에 직접 구현하지 않고 검증된 라이브러리를 씁니다. 제가 집중한 건 유사도 계산 자체보다 **검색 파이프라인을 조립하고 품질을 평가·운영하는 쪽**입니다."

**3단 콤보**: 원리는 안다(한 번 해봤다) + 실무에선 안 짠다(이유 있음) + 내 관심은 운영이다.

## 6. 백엔드/AX 직무 학습 범위 (어디까지 파야 하나)

| 구분 | 알아야 함 (조립·운영) | 몰라도 됨 (ML 엔지니어 영역) |
|---|---|---|
| 임베딩 | 텍스트→벡터, 의미 유사, 차원 수, 모델 교체 시 재적재 | 임베딩 모델 **학습**, 트랜스포머 내부 |
| 유사도 | 코사인이 뭘 재는지 (개념) | SIMD 최적화 구현 |
| Vector DB | pgvector 연결·insert·search, HNSW 존재 이유 | 인덱스 알고리즘 **직접 구현** |
| RAG | 검색→프롬프트 주입→생성 **조립**, 평가 | retriever 모델 파인튜닝 |

**핵심: 내 일은 부품을 "조립하고 운영"하는 것이지 부품을 "만드는" 것이 아니다.**
